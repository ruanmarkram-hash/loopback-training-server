# Host CLI coach

No inference API client, SDK, API key, billing fallback, shell bridge or network listener. `CliCoach.analyze` launches only the operator-selected absolute Codex executable with a fixed argument list and JSON stdin. The environment excludes inherited API keys, MCP configuration and deployment credentials. Existing ChatGPT credentials remain in the existing auth home and are never copied. Supported `codex login status` must report ChatGPT login; API-key login is refused.

The production worker must map authenticated, leased athlete-scoped backend jobs into `{version:1, correlationId, idempotencyKey, context}`. Context is an object bounded to 32 KiB. Adapter returns an assessment and up to ten proposal candidates, never mutations. Server remains responsible for ownership, eligible workout IDs, near-start/completed freezes, coherent composition, approval and leases. No backend worker is installed by this package.

Host constructor configuration requires absolute `executable`, `stateDir`, `killWrapper` and `authHome`. State directories and files use 0700/0600. Use the project's safe-kill wrapper. Configuration is trusted host input, never job fields. The configured executable and auth home require owner-controlled filesystem permissions. Default call timeout is 90 seconds, output/event bound 256 KiB, request bound 32 KiB, daily calls 20, daily reserved tokens 400,000 with 30,000 reserved per call. UTC day accounting is conservative and persisted before spawn. Reported usage is retained separately. Reservations estimate usage, cannot guarantee an absolute provider-token cap during an individual CLI call; there is no documented supported CLI output-token cap here. A call exceeding its reservation blocks subsequent work once total measured usage reaches the budget. No retries or repair calls occur inside the adapter.

Successful and failed attempt results, including uncertain reservations, persist through the following UTC day independently of daily counters. At most 200 current/prior-day attempts and seven daily accounting summaries are retained; a full cache fails closed. This exceeds the maximum ten-minute worker lease, while server durable logical job keys prevent repeats after bounded host retention expires. `interrupted` reservations survive process crashes and require explicit server retry with a new attempt idempotency key after lease recovery. Lock contention returns `busy`; a dead-owner worker lock is reclaimed only when its recorded owner and child PIDs are both absent, under a recovery mutex. Live owners or children remain busy. Durably quarantined execution cannot be reclaimed automatically even after both PIDs disappear; an unconfirmed owner crash requires supervision. Corrupt ownership metadata and an interrupted recovery mutex require supervised recovery; no process is guessed dead or killed. Runtime clock moving backwards cannot reset the current day. Budget JSON corruption fails closed. Server alone owns transient backoff and dead-lettering. Auth expiry, quota and validation failures preserve existing training.

Only `ok` may contain a valid output. Raw diagnostics stay out of result envelopes. Hashes, safe diagnostic categories, usage and exit status stay separate. Tool-execution item types cause `capability_violation`. A known CLI startup diagnostic saying the disabled Code Mode host is unavailable is explicitly recorded as `disabled_code_mode_startup`; the explicit under-development `skip_host_skill_discovery` warning is recorded as `host_skill_discovery_disabled_warning`. All other provider errors fail closed. The optional trusted `evidenceRecorder` is for synthetic verification only, because raw event streams contain context and model output. Production must leave it unset.

Timeout/cancellation terminate only the spawned child through `killWrapper`; failure to confirm exit enters `termination_failed` and quarantines this adapter instance. Supervision must confirm the reported child PID exited before recreating an instance or removing its retained worker lock. Never point the wrapper at unrelated processes.

Run regression checks with `COACH_KILL_WRAPPER` pointing to the configured safe wrapper and `npm test`. The explicit synthetic smoke requires `COACH_EXECUTABLE`, `COACH_AUTH_HOME`, `COACH_STATE_DIR`, `COACH_KILL_WRAPPER`, `COACH_EVIDENCE_FILE`; it contains no personal athlete data. No service, login, launchd, global configuration or deployment is changed.

## Supervised host worker

`worker.mjs` polls only the fixed application job endpoints `/api/coaching/worker/claim` and `/api/coaching/worker/jobs/{uuid}/result`. It never calls plan mutation, approval or dismissal endpoints. The backend must enforce a restricted athlete-scoped `coach_worker` token, never an ordinary athlete/admin token. Local HTTP is accepted only for loopback origins; remote origins require HTTPS. Redirects never forward the bearer token. Responses are bounded to 64 KiB and each HTTP attempt times out after five seconds by default. Result delivery retries at most three times with bounded backoff. Poll network backoff caps at sixty seconds and exits on cancellation. Auth or terminal adapter failures halt the worker with a visible status.

The private durable journal records one leased request and its adapter result before submission. After a lost HTTP response or host restart, result delivery reuses the journal and does not spend new inference. Backend re-leasing a transient attempt receives a distinct normalized adapter attempt key derived from the logical job key plus lease token, while correlation remains the durable job UUID. An expired/old lease never triggers fresh inference. Only the backend reclaims leases and owns maximum attempts/backoff. Model output cannot change the worker URL, token, CLI executable, arguments or result route. Candidate changes are submitted for backend validation and athlete approval; the worker cannot apply them.

CLI identity is pinned to `codex-cli 0.160.1`, the installed npm launcher SHA256, its official native Codex binary SHA256, and the running Node binary SHA256. The worker launches the pinned native binary directly, verifies all three files, checks native `--version`, and rejects changed binaries before claiming a job. Subsequent calls recheck file identity and hash on change. Credential lookup stays in the existing CLI auth home. Neither login credentials nor provider configuration are copied. No inference API key is inherited. Version/login probes have a five-second ceiling; inference retains the ninety-second ceiling, leaving margin inside the backend's 180-second lease.

Keep the token, pins, config, journal, budget and logs outside the source repository in an owner-only private directory. Configuration and token files must be owner-readable only (0600); worker state must be owner-only (0700). Host identity discovery reads installed package metadata and hashes existing executables without installing anything:

```sh
umask 077
node host-tools/cli-coach/identity.mjs /absolute/path/to/codex > /absolute/private/cli-pins.json
```

The operator creates a private `worker.json` with `baseUrl`, `tokenFile`, `stateDir`, `pins` (the generated pins object), `killWrapper`, `authHome`, and optionally `cliLimits`, `httpTimeoutMs`, `maxHttpAttempts`, `pollMs`. `cliLimits` permits only timeout/call/token/output bounds, never an executable or environment override. Paths must be absolute. Do not paste tokens into the command line or JSON config; `tokenFile` points to the separately issued restricted backend token. Do not include any of these private files in Git.

```sh
node host-tools/cli-coach/run-worker.mjs /absolute/private/worker.json --status
node host-tools/cli-coach/run-worker.mjs /absolute/private/worker.json --once
node host-tools/cli-coach/run-worker.mjs /absolute/private/worker.json
```

Status checks private files, executable pins, CLI version and saved login without claiming jobs or running inference; backend authentication is explicitly not checked. The once command processes at most one lease or pending delivery. The final command remains in the foreground and stops on SIGINT/SIGTERM. Structured stdout contains only status, job correlation, exit categories and counters, never context or tokens. Quiet/unchanged polls produce no inference and no repeated logs. This package installs no launch agent, service, container, tunnel or deployment. A supervisor must handle `termination_failed` using the retained adapter lock's own child PID and the configured safe process wrapper. Worker tests use a fake local job backend, while real supported-CLI integration evidence is separately recorded.

Generic supervisor/configuration examples are `worker-host.env.example` and `worker.config.example.json`. They intentionally contain no usable pins or tokens and must be populated in the private deployment route by its owner. The examples do not create or activate a service. A separate `worker-cli-smoke.mjs` starts an ephemeral authenticated loopback job fixture and exercises the real pinned CLI. It proves the host transport seam with synthetic data; it does not substitute for current-candidate backend/schema/ownership integration evidence.

Pending recovery first uses cache-only adapter lookup; a miss never invokes or reserves inference. Known completed results can be delivered even when fresh inference would exceed the remaining lease. Before spawning, the owned lock records a durable spawn intent. If recording its PID fails, safe termination is attempted and the adapter remains quarantined. Unknown-child intents cannot be reclaimed automatically after owner death; supervision must establish that the child is gone.

Version/login probes use the same durable child ownership and quarantine protocol as inference. Cache-lock contention is deferred without a definitive model result or result submission; the pending lease bounds recovery. Standalone inference calls cannot bypass adapter admission.
